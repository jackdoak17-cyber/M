# Shot Props Instagram MVP (Repo-Aligned)

## Goal

Add a fully automated Instagram carousel pipeline for the existing weekend `shot_props` posts in `M`, using the **same verified qualifier logic** as X (no duplicate filtering code).

Initial scope:

- `Potential Value` (weekend-combined, Friday)
- `High Probability` (Saturday morning)
- `High Probability` (Sunday morning)

## Current Foundation (Implemented)

The X `shot_props` generator now also writes **Instagram-ready carousel manifests**:

- `output/shot_props/instagram/{YYYY-MM-DD}_potential_value.json`
- `output/shot_props/instagram/{YYYY-MM-DD}_high_probability.json`

These manifests are built directly from the already-verified qualifier set in `src/shot_props/generate.py`.

## Why This Architecture

- Prevents drift between X and Instagram qualification logic.
- Guarantees Instagram content includes the same qualifying rows (starter-only hit rate, odds thresholds, etc.).
- Enables rendering/publishing to be treated as a pure transformation of a verified manifest.

## Manifest Shape (Renderer Contract)

Generated by `src/instagram/shot_props_manifest.py`.

Top-level fields include:

- `post_type`
- `scheduled_for`
- `source_target_date`
- `fixture_dates`
- `title`
- `intro`
- `caption`
- `thresholds`
- `counts`
- `sections.by_section`
- `slides`
- `content_fingerprint`
- `verification`

Important properties:

- `slides` includes a cover slide plus **auto-paginated** section slides.
- `sections.by_section` stores the canonical ordered qualifier rows.
- `verification` checks slide rows match canonical rows (counts + order/content via row ids).

## Completeness Guarantee

The manifest layer enforces:

- no silent truncation
- no dropped qualifiers due to fixed slide count assumptions
- duplicate row detection within a section

This solves the key Instagram risk: a 4-slide design is not enough on larger days.

## Scheduling Alignment (Existing Weekend X Cadence)

Current X timing (UK local, DST-safe) should be mirrored for Instagram later:

- Friday `17:00` preview (`Potential Value`)
- Friday `18:00` post (`Potential Value`)
- Saturday `07:30` preview (`High Probability`)
- Saturday `09:15` post (`High Probability`)
- Sunday `07:30` preview (`High Probability`)
- Sunday `09:15` post (`High Probability`)

Shot-props content generation is already close to post time:

- Friday `16:00` UK (weekend value + Saturday high-prob)
- Saturday `07:15` UK (Saturday refresh)
- Sunday `07:15` UK (Sunday high-prob)

## Modules Added (Instagram Scaffold)

- `src/instagram/shot_props_manifest.py`
  - manifest builder
  - deterministic caption builder
  - pagination
  - manifest verification
- `src/instagram/manifest_io.py`
  - manifest path resolution/loading helpers for shot-props
- `src/instagram/meta_graph.py`
  - minimal Meta Graph API carousel publishing client
- `src/instagram/renderer.py`
  - branded slide HTML generation (from manifest)
  - HTML QA bundle writer
  - Playwright CLI image rendering entry point (JPEG/PNG)
- `src/instagram/render_shot_props_carousel.py`
  - CLI to render from a manifest path or shot-props target date
- `src/posting/telegram_client.py`
  - `send_photo(...)`
  - `send_media_group(...)` for future Instagram previews

4. Publisher Workflow

- Add `send_previews_instagram.yml`

5. Token Maintenance

- Add scheduled Meta token refresh job and alerting

## Acceptance Criteria for Live Launch

- Every qualifying row in manifest appears on exactly one section slide.
- Rendered slide count matches manifest slide count.
- Telegram preview uses the same rendered image files that are posted.
- Approval is invalidated if manifest/render output changes after approval.
- Meta publish result (media id + permalink) is logged back to Telegram/Supabase.
